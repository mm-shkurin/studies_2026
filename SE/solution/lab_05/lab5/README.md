## Процесс ЛР 5: Покупка билета

### Границы
- **Цель:** оформить оплаченную бронь выбранного рейса и места для пассажира.
- **Вход:** запрос пассажира (даты, маршрут), актуальный каталог рейсов, прайс, доступность мест.
- **Начало:** обращение пассажира к каналу продаж (сайт / киоск / касса).
- **Конец:** оплаченный билет выдан **или** отказ (нет мест / отказ оплаты) с освобождением удержания.
- **Вне границы:** онлайн-регистрация на рейс, изменение брони после оплаты, планирование сетки рейсов.

### Поля шаблона (обязательно заполнить)
1. Название: «Описание бизнес-процесса покупки авиабилета».
2. **Цель.**
3. **Перечень действий** — нумерованный; у каждого шага тайминг («мгновенно», «в течение N минут»…); развилки — подпунктами (как 5.1 / 5.2 в шаблоне).
4. **Реализация процесса** — общая длительность экземпляра.
5. **Сопровождение** — каналы обмена, контроль (номер брони, id платежа, версия удержания места).
6. **Результат** — минимум 2 исхода (успех / отказ).
7. **Ресурсы.**
8. **Исполнитель** (пассажир + система продаж / кассир — зафиксировать роли).
9. **KPI** (доля успешных оплат, время до подтверждения, доля сорванных удержаний по TTL).

### Рекомендуемый каркас действий
1. Приём запроса пассажира (маршрут, даты).
2. Поиск рейсов в каталоге.
3. XOR: рейсы найдены? Нет → конец «отказ поиска».
4. Выбор рейса и места.
5. Удержание места (hold) с TTL.
6. Расчёт стоимости, выставление счёта / платёж.
7. XOR: оплата подтверждена?
   - Нет / таймаут → снять hold → конец «отказ оплаты».
   - Да → зафиксировать продажу в постоянном хранилище → выдать электронный билет / номер брони.
8. (Опционально) отправка уведомления — через send/service task; сбой уведомления не откатывает оплату.

Числовые SLA из примера «учебный центр» **не копировать**; писать порядок контроля времени без выдуманного норматива, если регламент аэропорта не дан.

### BPMN: что должно быть на схеме
Ориентир — табл. 1 в `lab_5_REPORT.md`:

| Элемент | Зачем здесь |
|---|---|
| Пул(ы) | Пассажир / Система продаж / (опц.) Платёжный провайдер |
| Message start / start | Начало по обращению |
| User / Service / Send task | Выбор рейса; hold и запись продажи; уведомление |
| XOR | Есть ли рейсы; успешна ли оплата |
| Sequence flow | Внутри пула |
| Message flow | Между пассажиром, системой и платёжкой |
| End event | Отдельный конец на каждую ветвь результата |

`isExecutable=false` допустим: это описательная учебная модель, не внедрённая BPMS.
