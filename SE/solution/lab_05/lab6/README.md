## Процесс 2. Онлайн-регистрация на рейс

**Цель:** зарегистрировать пассажира на оплаченный рейс и выдать посадочный талон.  
**Вход:** оплаченная бронь (из процесса покупки), паспортные/документные данные, схема мест.  
**Не входит:** первичная продажа билета; изменение маршрута «с нуля».

Каркас действий:
1. Пассажир открывает регистрацию (рейс, бронь).
2. Проверка: бронь оплачена и окно регистрации открыто?
3. XOR: отказ → конец «регистрация недоступна».
4. Выбор/подтверждение места (если не зафиксировано).
5. Фиксация регистрации, формирование посадочного талона.
6. Отправка талона пассажиру.
7. XOR (опц.): нужна ли доп. услуга багажа — вне основного успеха или отдельная ветвь.

KPI (пример): доля регистраций до закрытия окна; время от открытия формы до выдачи талона.

## Процесс 3. Управление бронированием

**Цель:** изменить параметры уже созданной брони (дата/рейс/место) в допустимых правилах перевозчика.  
**Вход:** действующая бронь, запрос изменений, актуальная доступность.  
**Не входит:** первичная покупка; полный возврат (это процесс 4).

Каркас действий:
1. Запрос изменения от пассажира.
2. Проверка статуса брони и правил тарифа.
3. XOR: изменение запрещено → отказ с причиной.
4. Поиск альтернативы (рейс/место).
5. XOR: альтернативы нет → отказ.
6. Пересчёт доплаты / возврата разницы.
7. Подтверждение пассажиром → фиксация новой версии брони → уведомление.

KPI: доля изменений с первой попытки; число циклов доработки; время до подтверждения новой версии.

---

## Процесс 4. Отмена регистрации / возврат

**Цель:** отменить регистрацию и/или оформить возврат с освобождением места по правилам тарифа и времени до вылета.  
**Вход:** бронь/талон, запрос отмены, правила возврата.  
**Не входит:** продажа нового билета (возврат к процессу 1 отдельным экземпляром).

Каркас действий:
1. Запрос отмены/возврата.
2. Определение стадии: только check-in / оплаченный билет / уже посадка.
3. XOR: после посадки → отказ в возврате.
4. Снятие регистрации (если была) → освобождение места.
5. Проверка права на возврат денег (`canRefund` из ЛР 4).
6. XOR: возврат разрешён → инициировать возврат платежа → конец «возврат оформлен»; иначе конец «отмена без возврата» / «отказ».

KPI: доля возвратов с прослеживаемым id платежа; время до освобождения места.

## Процесс 5. Планирование рейсов и мест

**Цель:** утвердить расписание рейсов и квоты мест на период (ручное планирование из домена авиаперевозок).  
**Вход:** спрос/статистика, ограничения флота, действующая версия расписания.  
**Не входит:** продажа билетов и регистрация пассажиров.

Каркас действий:
1. Сбор исходных данных (маршруты, спрос, доступный флот).
2. Черновик расписания и квот.
3. Проверка ограничений (два маршрута / сезонность — уточнить по указанию преподавателя).
4. Согласование с ответственным.
5. XOR: замечания → доработка черновика (цикл).
6. Фиксация утверждённой версии расписания → публикация в каталог рейсов (вход для процесса покупки).

KPI: циклы согласования; время от черновика до утверждённой версии; доля рейсов без квоты.

## Пошаговый план работы

1. Убедиться, что ЛР 5 сдана или хотя бы готов паспорт процесса №1 (на него ссылается таблица покрытия).
2. Для каждого из процессов 2–5 заполнить **все** поля шаблона (как в ЛР 5).
3. Нарисовать 4 BPMN; имена файлов — из таблицы выше.
4. В обоснованиях подчеркнуть границы: регистрация не продаёт билет; планирование не считает нагрузку кассы; отмена согласована со статусами ЛР 4.
5. Раздел «Согласованность»: одни и те же идентификаторы брони/рейса; версия расписания как вход каталога.
6. Собрать отчёт → DOCX (титул ФИТ-242).

### Элементы BPMN (минимум на каждой схеме)
Пулы участников, стартовое событие, user/service/send задачи по смыслу, XOR с default-ветвью где нужно, sequence/message flow без путаницы, отдельные end event на исходы.
