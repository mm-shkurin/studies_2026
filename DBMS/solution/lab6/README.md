## Описание представлений

### Простые представления (CREATE VIEW)

#### v_driver_team_results
Объединяет таблицы drivers, teams, cars, races, tracks, results. Показывает пилотов, их команды, болиды и результаты гонок.

Поля:
- driver_ID, driver_name, driver_country
- team_ID, team_name, team_base
- car_ID, car_model, car_year
- race_ID, race_name, race_date
- track_name, track_country, track_length
- position, points

#### v_race_details
Объединяет таблицы races, tracks, sponsors. Показывает детали гонок с трассами и спонсорами.

Поля:
- race_ID, race_name, race_date
- track_ID, track_name, track_country, track_length
- sponsor_ID, sponsor_name, sponsor_budget

#### v_car_parts
Объединяет таблицы cars, parts, car_parts. Показывает запчасти, установленные в болидах.

Поля:
- car_ID, car_model, car_year, team_name
- part_ID, part_name, part_type

### Материализованные представления (CREATE MATERIALIZED VIEW)

#### mv_driver_standings
Агрегирует очки каждого пилота по всем гонкам. Хранит вычисленные данные.

Поля:
- driver_ID, driver_name, driver_country, team_name
- races_completed, total_points, avg_points, max_points, best_position

#### mv_team_standings
Агрегирует очки всех пилотов каждой команды. Хранит вычисленные данные.

Поля:
- team_ID, team_name, team_base
- driver_count, total_races, total_points, avg_points_per_driver

## Описание запросов к представлениям

### a) Запрос с вложенным запросом
**Назначение:** Найти пилотов, чей средний балл выше среднего по всем пилотам.

**Используемое представление:** `mv_driver_standings`

**Логика:**
- Вложенный запрос вычисляет среднее значение `avg_points` по всем пилотам
- Внешний запрос выбирает пилотов, у которых `avg_points` выше этого среднего
- Сортировка по убыванию среднего балла

Источник: пособие, стр. 112–116

### b) Запрос с группировкой и простой сортировкой
**Назначение:** Подсчитать количество гонок на каждой трассе.

**Используемое представление:** `v_race_details`

**Логика:**
- Группировка по трассе (название и страна)
- Подсчёт количества гонок (`COUNT(race_ID)`)
- Сортировка по убыванию количества гонок

Источник: пособие, стр. 104

### c) Запрос с группировкой с условием и многоуровневой сортировкой
**Назначение:** Показать пилотов с суммой очков > 15 с многоуровневой сортировкой.

**Используемое представление:** `mv_driver_standings`

**Логика:**
- Фильтр: `total_points > 15` (условие WHERE)
- Группировка по ID пилота, имени, команде, количеству гонок и очкам
- Сортировка:
  1. По очкам в убывающем порядке (`DESC`)
  2. По названию команды в возрастающем порядке (`ASC`)
  3. По имени пилота в возрастающем порядке (`ASC`)

Источник: пособие, стр. 104

## Обновление материализованных представлений

Материализованные представления хранят данные и требуют обновления при изменении базовых таблиц:

```sql
REFRESH MATERIALIZED VIEW mv_driver_standings;
REFRESH MATERIALIZED VIEW mv_team_standings;
```

Источник: пособие, стр. 120

## Удаление представлений

При необходимости представления можно удалить:

```sql
DROP VIEW IF EXISTS v_driver_team_results;
DROP VIEW IF EXISTS v_race_details;
DROP VIEW IF EXISTS v_car_parts;
DROP MATERIALIZED VIEW IF EXISTS mv_driver_standings;
DROP MATERIALIZED VIEW IF EXISTS mv_team_standings;
```

Источник: пособие, стр. 119–120

## Преимущества представлений

1. **Упрощение разграничения прав доступа** — разным пользователям разные представления данных
2. **Упрощение запросов** — сложные запросы скрыты внутри представлений
3. **Снижение зависимости от изменений структуры** — интерфейс представления остаётся стабильным
4. **Ускорение сложных запросов** — материализованные представления хранят заранее вычисленные данные

Источник: пособие, стр. 120–121
